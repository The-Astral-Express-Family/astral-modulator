# 用户资料系统：头像（外链 URL）+ 用户名 + 个性签名

已确认决策：头像走**仅外链 URL**（不做上传基础设施）；入口用**侧边栏底部用户菜单**（头像+用户名+下拉菜单）。

现状要点：`Actor` 已有 `DisplayName`（即用户名，可编辑化即可）；缺 `bio`/`avatar_url`。**附带发现一个潜伏 bug**：auth 模块把 `model.Actor`（无 json tag）直接嵌进 `/auth/register`、`/auth/login`、`/auth/me` 响应 → 实际返回 PascalCase `"DisplayName"`，与 openapi.yaml/前端的 `display_name` 不符（auth E2E 未点验所以没暴露）。本次顺带修复。

## 一、后端（server，Go + chi + GORM + goose）

### 1. 迁移 `server/migrations/00012_actor_profile.sql`
```sql
-- +goose Up
ALTER TABLE actors ADD COLUMN bio TEXT NOT NULL DEFAULT '';
ALTER TABLE actors ADD COLUMN avatar_url TEXT;   -- NULL=未设置
-- +goose Down
ALTER TABLE actors DROP COLUMN avatar_url;
ALTER TABLE actors DROP COLUMN bio;
```
无新表 → `testsupport/db.go` 的 AutoMigrate 列表无需改（Actor 已在列，新列自动带上）。

### 2. `server/internal/model/model.go`
`Actor` 增 `Bio string \`gorm:"size:500"\``、`AvatarURL *string \`gorm:"size:500"\``（注释指回 00012，遵循文件头的三方同步纪律）。

### 3. auth 模块（module.go + service.go）
- 新增 **actorDTO**（`id/kind/display_name/bio/avatar_url`，snake_case json tag，仿 workspace 模块已有 actorDTO 模式），`MeResponse.Actor` 改用 DTO —— register/login/me 三处全部替换，修掉 PascalCase 漂移。
- `MeResponse` 增 `Email`（human 查 `human_auth` 填入；agent/service 省略），供资料页只读展示。
- 新端点 **`PATCH /auth/me`**（挂 `RegisterPrivate`）：
  - body `{display_name?, bio?, avatar_url?}`，指针字段 = 部分更新语义（不出现的字段不动）
  - 校验（`httpx.Invalid` → 400 VALIDATION_FAILED）：display_name 给则 trim 非空、≤200；bio 给则 ≤500（rune 计数，中文友好）；avatar_url 给则空串（=清除）或 http(s) URL、≤500（拒绝 `javascript:` 等其他 scheme；服务端**不抓取**该 URL，无 SSRF 面）
  - 任意已认证 principal 更新自己的 actor（human session / agent credential 均可）
  - 响应 200 返回 `Me`（更新后的 DTO）
- DTO 输出约定：`bio`/`avatar_url` 恒为 string，空串=未设置（前端类型最简）；模型层 `*string` 映射 NULL。

### 4. 契约同步（强约束，缺一 CI 即红）
- `api/openapi.yaml`：`Actor` schema + `bio`/`avatar_url`；`Me` + `email`（nullable）；新增 `PATCH /auth/me` operation（openapi_contract_test.go 自动比对路由↔规范）。
- `TODO.md` §9 契约变更登记表追加一行（model.go 头注释要求的流程）。

### 5. 测试（auth 模块，sqlite）
- PATCH 成功改名/签名/头像 URL；三项各自校验失败（空名、超长 bio、非法 scheme）400；空串 avatar_url 清除回 NULL。
- `/auth/me` 回归断言：snake_case 字段名 + human email。

## 二、前端（web，Vue3 + shadcn-vue）

### 1. API 层
- `types.ts`：`Actor` + `bio: string`、`avatar_url: string`；`MeResponse` + `email?: string`。
- `api/modules/auth.ts`：`updateMe(body)` → `PATCH /api/v1/auth/me`。

### 2. shadcn 组件补齐
`add avatar、dropdown-menu、textarea` 三个组件（本机代理下 CLI 需 preload shim + 根 tsconfig paths 的绕行方案，此前用过；若 CLI 仍挂则从 shadcn-vue 官方仓库手工 vendor 这三个小组件，均为 reka-ui 薄封装）。

### 3. 通用组件 `components/shared/UserAvatar.vue`
props：actor + 尺寸。`AvatarImage`（avatar_url 非空时；加载失败自动回退）+ `AvatarFallback`（display_name 首字符 + 按 actor id 确定性配色），登录页外处处复用。

### 4. SessionBox.vue 升级为用户菜单
登录态：触发按钮 = UserAvatar(sm) + display_name + chevron → DropdownMenu（label 区显示名字+邮箱；「个人资料」→ `/profile`；分隔线；「登出」）。未登录保持现有登录按钮。

### 5. 新页面 `views/ProfileView.vue` + 路由
- 路由 `/profile`（MainLayout 子路由，`meta: { auth: 'required' }`）。
- Card 布局（沿用 LoginView 的 Field/FieldGroup/Input + useApiAction 惯例）：头像预览（UserAvatar 大号，随 URL 输入即时预览）；头像 URL Input（可留空）；用户名 Input；个性签名 Textarea + 0/500 计数；邮箱只读灰显。
- 保存 → `updateMe` → 成功回写 `session.actor` + sonner toast；表单校验与后端规则一致（前端 maxlength + 提交前 trim 校验）。
