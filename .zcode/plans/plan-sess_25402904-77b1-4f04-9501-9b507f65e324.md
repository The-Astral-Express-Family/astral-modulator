# 交互式服务端 bootstrap 命令（cmd/astral-bootstrap）

## 目标

把现在的手工 bootstrap 流程（cp .env.example → 手改 → go run → curl POST /auth/register 建首个账号）替换为一个交互式 Go 向导：

```
cd server && go run ./cmd/astral-bootstrap
```

向导一次性完成：配置问答 → 数据库连通性验证（失败可重试）→ goose 迁移 → server_id 固化 → 写 server/.env → 创建首个 human 管理员账号（复用现有 auth.Service.Register，含"已有 human 则关闭"守卫）。全程幂等，可安全重复运行。**不启动 HTTP 服务**，结束时打印下一步指令。

形态（已确认）：**独立二进制 + 标准库交互 + golang.org/x/term（新增唯一直接依赖，密码掩码）**。

## 新增文件

```
server/cmd/astral-bootstrap/main.go        # 薄入口：校验 TTY、调 bootstrap.Run
server/internal/bootstrap/bootstrap.go     # Run()：向导流程编排

server/internal/bootstrap/validate.go      # DSN/邮箱/密码本地校验（镜像 auth.validatePassword 规则）
server/internal/bootstrap/envfile_test.go  # 合并/写回/备份单测
server/internal/bootstrap/validate_test.go # 校验单测
```

修改：`server/go.mod`（+golang.org/x/term）、`README.md`（快速开始增加向导路径，保留手工路径作备选）。

## 向导流程（bootstrap.Run）

1. **预载当前值作默认**：godotenv.Load()（与 main.go:44 相同语义）→ config.Load()，现有 .env/环境变量的值成为各提示的默认值。
2. **配置问答**：数据库 DSN（默认取当前值或 `postgres://astral:astral@localhost:5433/astral?sslmode=disable`；留空需确认进入桩模式）、HTTP addr（默认 :8080）、PublicURL（可空）、AutoMigrate（默认 true）、LogLevel（默认 info）、DevCORSOrigins（可空）。
3. **连通性验证**：store.Open(ctx, dsn, false, 静音 logger)（复用 db.go:25，不迁移；传入写 io.Discard 的 slog 以保持控制台干净）。失败 → 打印原因，循环重试（重输 DSN / 放弃）。
4. **迁移**：store.Migrate(ctx, sqlDB)（db.go:53，goose 幂等 up）；best-effort 打印 goose 版本号。
5. **server_id**：store.EnsureServerID(ctx, gormDB, 问答值)（db.go:89），打印最终生效值（库值优先时说明）。
6. **写 .env**：展示全部所选值 → 确认 → 备份旧文件为 `.env.bak` → 以带注释的规范模板写出已知键，未知已有键合并保留（godotenv.Read 解析）。
7. **首个管理员**（DSN 非空时）：count Actor(kind=human)；=0 → 询问是否现在创建（默认是）：邮箱、显示名（默认取邮箱前缀）、密码掩码输入两次（x/term.ReadPassword；非 TTY 降级明文并警告）；直接调 auth.NewService(db, log).Register(ctx, RegisterInput{...})（service.go:165，复用其邮箱/密码校验、bcrypt、事务与 403 守卫），密码校验失败就重新提示。>0 → 打印"bootstrap 已完成过，跳过"。
8. **总结**：脱敏摘要（DSN 只显示 host/db）+ `.env` 路径 + server_id + 管理员邮箱 + 下一步 `go run ./cmd/astral-server` / web 控制台登录提示。
9. **中断处理**：signal.NotifyContext；提示阶段 Ctrl+C/EOF → 打印 "aborted"，不写任何文件（.env 只在第 6 步确认后落盘）。

## 复用与不做的事

- 复用：config.Load、store.Open/Migrate/EnsureServerID、auth.Service.Register、httpx.APIError.Message 渲染错误。
- 不改现有 main.go、不动 POST /auth/register 端点（向导只是同一条 Service.Register 路径的 CLI 入口）。
- 不引入 cobra：单命令无子命令需求，os.Args 仅留位置给未来的用法提示。

## 验证

1. `cd server && gofmt -l . && go vet ./... && go build ./... && go test ./... -count=1`（含新单测：envfile 合并保留未知键/备份生成、validate 规则）。
2. E2E（不碰你本机 5432/在跑的后端）：起临时容器 `docker run --rm -d -p 5544:5432 -e POSTGRES_USER=astral -e POSTGRES_PASSWORD=astral -e POSTGRES_DB=astral postgres:17-alpine`，以管道输入驱动向导（非 TTY 密码降级路径顺带被测到），断言：.env/.env.bak 生成、server_meta 与 actors/human_auth 落库、重复运行第二轮跳过管理员创建。
3. 用生成的 .env 短暂启动 astral-server，curl /healthz、/readyz、/api/v1/auth/login 验证账号可用，随后停掉、销毁临时容器、清理测试 .env（恢复现场）。
