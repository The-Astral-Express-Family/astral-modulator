# ADR-0001: CLI 使用 C++20

- Status: Proposed
- Date: 2026-09-06

## Context

项目希望部分使用 C++，其中 CLI 是最适合发挥 C++ 优势的边界：启动快、可生成原生二进制、容易被 Agent/脚本高频调用，也能避免要求终端用户安装 Node/Python/Java Runtime。

CLI 还必须覆盖 Windows、macOS、Linux，因此编译器与依赖兼容性比追求最新语言特性更重要。

## Decision

CLI 使用 C++20。

推荐基线：

- CMake + CMake Presets；
- vcpkg manifest mode；
- CLI11；
- libcurl；
- nlohmann/json；
- spdlog；
- Catch2 或 GoogleTest。

暂不要求 C++23。

## Consequences

### Positive

- 原生启动体验；
- 单二进制/少依赖分发可行；
- 三端编译器成熟；
- 与服务端语言解耦。

### Negative

- OS keychain、签名、路径等平台差异需要封装；
- 依赖静态/动态链接策略需要单独测试；
- HTTP/JSON 业务代码开发速度可能低于 Go/Rust/TS。

## Alternatives

- Rust CLI：分发也优秀，但不满足当前“项目部分使用 C++”的首选方向；
- Go CLI：构建最简单，但不使用 C++；
- Node/Python CLI：迭代快，但 Runtime/启动/分发体验不是本项目首选。
